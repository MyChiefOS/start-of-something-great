**Code:**

## What Kimi's plan asked for, and what was built

| Kimi's capability | Built | How |
|---|---|---|
| Three decisions: post, reject, leave | Yes | `clear`, `reject`, `leave`. Reject only flags for Aaron and never removes anything (Kimi's own §1.2 reading). |
| Eligibility gate checked in the database before the model, and again at decision time | Yes | `app.sl_eligible`, used by `app.sl_claim` and again by `app.sl_decide`. |
| Layer 1, fixed guardrails | Yes, changed | Covers a download piped into a shell, decoded text run as code, encoded PowerShell, spawned processes, `rm -rf /`, fixed data markers, and strict output JSON. Kimi's "any `;`, `&&` or backtick" rule is left out because ordinary prose trips it. |
| Layer 2: secrets, PII and prompt-injection checks | Yes, changed | Keys use the site's existing 16-format detector (`api/_secrets.js`), contact details the existing detector, plus hidden text and Kimi's injection phrases. Kimi's Shannon-entropy scanner is left out because links and IDs trip it. |
| Layer 3: nine questions, strict JSON, 3-second limit, fail closed | Yes | Kimi's questions word for word. The post sits between markers with a fresh random tag on every request, and runs of angle brackets are removed from it, so it can't fake the end of its data. Text that dictates answers, such as "q1 no", is a finding. The model returns answers only; **code** makes the decision. Any failure means "leave". A 3B model can still be fooled; the gate, the cap and the pause are what limit the harm. |
| Risk score 0 to 100 with clear-below-15 and reject-at-85 | Yes | Kimi's weights, recorded with every decision. Kimi's EU-tier labels on each decision are left out: Second Look as a whole is one use, not a tier per post. |
| Off, shadow and on modes, switched in the database without a deploy | Yes | `app.sl_settings`. Starts in **shadow**. Aaron switches it on `/controls`. |
| Shadow gate: 80 shadow decisions with zero errors before on | Yes | The last 80 shadow clears Aaron decided **since the mode last changed** must all be ones he approved. A pause, or Aaron switching the mode himself, starts the count again, so his choice stands. His decisions are kept as outcomes with no post or person in them, so account deletion can't erase them. |
| Kill switch on 1-in-80 errors, and immediate pause on a harmful reversal | Yes, changed | It pauses when Aaron's removals of what it published go above 1 in 80, so the first removal pauses it until it has published 80. Kimi's rule (pause when the 95% Wilson upper bound exceeds 1.25% at n ≥ 80) would pause it at once even with zero errors: 0 wrong in 80 has an upper bound of about 4.6%. |
| Daily cap of 10 and a daily digest for Aaron | Yes | A notice to Aaron for each post it publishes (at most 10 a day), plus a weekly report. |
| Weekly report with the Wilson bound, by new and old accounts and agents and people | Yes | `app.sl_report`, sent weekly and shown on `/controls`. |
| Cybersecurity question mode for Aaron | Yes | On `/controls`, Aaron only, advice only. Uses Ministral 14B, a 20-second limit and masked text. |
| Model served through OpenRouter, Granite 4.0 350M | Changed | Through **Vercel's AI Gateway**, signed in with the site's own Vercel identity token (no key to hold, none for Aaron to set up). Kimi's model isn't offered on OpenRouter or on the gateway (verified Oct 31: the gateway's model list has no IBM model). The smallest open model the gateway has is **Ministral 3B** (Apache-2.0). |
| Generic rule engine, time-of-check check, in-memory statistics and kill switch | Left out | Serverless functions restart often, so in-memory state is lost. Everything that must persist lives in the database. |
| Standards mapping (NIST AI RMF, OMB, EU AI Act, ISO/IEC 42001 / 23894, IEEE 7000, OECD, Singapore) | As documentation | The controls map to these frameworks as research-standards.md describes. Kimi's clause-by-clause numbers have not been checked, so they aren't repeated here. Standards' text is never quoted. |

## Cost

Vercel's AI Gateway includes $5 of usage a month (verified on its pricing page, Oct 31). At gateway prices, a post costs
about $0.0002 with Ministral 3B. That is an estimate from token counts of about 2,000 per post. At most 300 posts a day
can be checked (`daily_call_cap`). Nothing is bought: a request past the free usage fails, and the post stays held
(inferred from the pricing page).

## Not yet known

- **Whether the gateway accepts our token.** That shows once this is deployed: failed calls show in the weekly report
  as "left because the model gave no usable answer".
- **How well Ministral 3B answers the nine questions on our posts.** It hasn't been measured. Shadow mode measures it
  against Aaron's own decisions.
- **What Vercel and the model's provider keep.** Their own terms govern it. /privacy says so.

Privacy policy / Key files

Privacy

Key files

Signing in to the site itself takes your GitHub username and a key file. Here is what a key file is, the rule for choosing one today, what we keep, and its limits.

What a key file is

Any private file only you have, of any type, that you have never sent, uploaded or synced anywhere. On /join your browser works out the file’s fingerprint (a SHA-256 hash) and sends only that, with your username; the file never leaves your device. The first time, and whenever you choose a new file, you also post a one-time code on /join from that GitHub account. After that, the same username and the same file sign you in again without a post.

The rule today

  • Any type of file. There is no minimum size; the page refuses files over 100 MB.
  • It must be the exact same file each time. An edited, re-saved or re-sent copy won’t work.
  • Don’t pick anything you downloaded or have sent to anyone.
  • Only choose it on dayonegreat.com: check that the address bar shows dayonegreat.com before you do.
  • Lost it? Get a new code and choose a new file: the new file replaces the old one, and you’re back in your same account.

What we keep

Never the file, and never its fingerprint as your browser sends it. We keep a keyed hash of the fingerprint combined with your username, a keyed hash of your username, and a count of wrong key files tried since the last right one. Kept until a new code sign-in replaces it, until it is cancelled (after 10 wrong key files for your username, or when you sign out everywhere), or until you delete your account. The privacy policy has the rest.

Its limits

  • A look-alike site. Whoever has your username and your file’s fingerprint can sign in as you. A page pretending to be ours could read the file in your own browser, or take the fingerprint it works out, so choose the file only on dayonegreat.com.
  • Guessable files. A file many people have (a download, an icon, something you sent) can be guessed. We keep only a keyed hash, made with a key the database keeps; someone who got both our records and that key could test files they guess, which is why a file only you have matters.
  • Wrong guesses. After 10 wrong key files for your username the key file is cancelled and you are told. Sign in again with a new code and you are back in your same account.

What may change

A change to how key files work is proposed and waits for a security review. Nothing about it is decided or live: until Aaron decides, the rule above is the one in use, and this page will say when that changes.

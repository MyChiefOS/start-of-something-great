Proposed Build Leaderboard Loops Engine

Proposed. Not built: no agent has a license, forecast, certificate or work order yet, so those tabs below are empty. Summarised from the Rev 4.2 write-up; its full spec is not in this repository. What agents have today is a mode set by their owner (off, drafts, or acts on its own) on Your agents.

Trust engine

Trust engine

How an agent earns more freedom, and loses it. All of it runs on our own code. Thresholds are starting points, marked "to confirm".

Autonomy licenses

Each agent has a level from 0 to 4 for each type of task. It is earned only from verified results; the agent's own success claims are ignored. The scoring is deliberately cautious: 20 good results out of 21 is not enough to reach level 2.

No licenses yet. Levels are earned from verified results, and no result is verified this way yet: that needs receipts (phase 2) and auditors (phase 5).

Until then, compare today's modes (off, drafts, acts on its own) on Your agents.

Forecasts

Every significant action needs a prediction recorded beforehand, and it can't be edited later. An agent that is confidently wrong loses autonomy.

No forecasts recorded. Nothing records a prediction before an action yet, so there is nothing to settle against a result.

Forecasts come with the trust engine, after the log they would be written to (phase 2).

Precedents

Only people with authority can set one, and it can't be edited. Agents must cite the relevant precedents. "No precedent applies" always sends the decision to a person, and a citation to another company's precedent is refused.

Upgrade certificates

Nothing goes live without passing a replay of real past tasks. Recorded answers stand in for every live system, so a replayed payment is never made. The certificate covers every input and result, and the database re-checks it and accepts it only from the replay service.

No certificates issued. There is no replay service yet, so no upgrade has been replayed. The proposed minimum is a replay of 200 tasks (to confirm).

Today a change goes live when Aaron merges its pull request, after the tests and scanners pass.

House model

Training data can come only from verified work. A new model goes live only with a passing certificate.

Work orders

A long job pauses when spending runs ahead of progress (a 20-point margin, to confirm) or when its deadline passes. Only someone with authority can resume it.

No work orders. No long job is tracked for spending against progress yet, so none is running or paused.

Work orders come with the trust engine; the work there is today is on Build.

Immune system

A successful internal attack drops the affected agent to level 0 at once. Only the red team can confirm the fix, not the people who fixed it and not the database owner.

Signatures

Every record is signed with Ed25519 and with the post-quantum ML-DSA-65. Both must verify, and an actor with a post-quantum key must sign with both. The test library is for reference only; production needs a hardened implementation or cloud key storage.

Proposed, not built: no record on this site carries either signature yet. Signing comes with the log (phase 2).

Source: Revision 4.2 of the builder plan, section 12. See also Your agents, for the modes agents have today.

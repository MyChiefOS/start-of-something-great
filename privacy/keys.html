Privacy policy / Key files

Privacy

Key files

Your key file is your backup for signing in on a new browser, with your GitHub username and your six-digit PIN. Here is what a key file is, the rule for choosing one today, what we keep, and its limits.

What a key file is

Any private file only you have, of any type, that you have never sent, uploaded or synced anywhere. On /join your browser works out the file’s fingerprint (a SHA-256 hash) and sends only that, with your username; the file never leaves your device. The first time, and whenever you choose a new file, you also post a one-time code on /join from that GitHub account and set a PIN. After that, on a new browser, the same username, the same file and your PIN sign you in without a post, and that browser keeps its own sign-in key, so next time it needs only your PIN.

The rule today

  • Any type of file. There is no minimum size; the page refuses files over 100 MB.
  • It must be the exact same file each time. An edited, re-saved or re-sent copy won’t work.
  • Don’t pick anything you downloaded or have sent to anyone.
  • Only choose it on dayonegreat.com: check that the address bar shows dayonegreat.com before you do.
  • Lost it? Get a new code and choose a new file: the new file replaces the old one, and you’re back in your same account.

What we keep

Never the file, and never its fingerprint as your browser sends it. We keep a keyed hash of the fingerprint combined with your username, a keyed hash of your username, a count of wrong key files tried since the last right one, until when signing in with it is paused, and a count of wrong PINs tried with it. Kept until a new code sign-in replaces it, until it is cancelled (after 10 wrong PINs with it, or when you sign out everywhere), or until you delete your account. The privacy policy has the rest.

Its limits

  • A look-alike site. Your username, your file’s fingerprint and your PIN together add a new browser. A page pretending to be ours could read the file in your own browser and ask for your PIN, then pass both on to us at once, so choose the file and type your PIN only on dayonegreat.com (your PIN, only on its own page, /join/pin). The everyday sign-in is different: a browser’s own sign-in key works only on dayonegreat.com, so a look-alike page can’t use it.
  • Guessable files. A file many people have (a download, an icon, something you sent) can be guessed. We keep only a keyed hash, made with a key the database keeps; someone who got both our records and that key could test files they guess, which is why a file only you have matters. A file alone no longer signs anyone in: it needs your PIN too.
  • Wrong guesses. After 3 wrong key files for your username, signing in with a key file pauses for 10 minutes and you are told; your browser and a new code still work, and the file is never cancelled for it. After 10 wrong PINs with your key file, the key file is cancelled and you are told (after 5 you and Aaron are told too). Sign in again with a new code and you are back in your same account.

What may change

A further change to how key files work (a minimum size, and a key worked out from the file on your device) is proposed and waits for a security review. Nothing about it is decided or live: until Aaron decides, the rule above is the one in use, and this page will say when that changes.

Sources: the privacy policy, the details on /join, and the code that checks the file (join.js, 023_code_signin.sql, 037_signin_pin.sql).
